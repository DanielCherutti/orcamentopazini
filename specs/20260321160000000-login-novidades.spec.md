# Card de novidades na tela de login

## 1. Contexto e Objetivo
- **Contexto:** A tela de login é o primeiro contato de muitos usuários com o sistema.
- **Objetivo:** Exibir um **card de novidades** com melhorias e novidades recentes, em linguagem clara, sem exigir login.
- **Escopo:** Apenas a rota pública de login (`/`). Conteúdo mantido no repositório (atualização manual por release).

## 2. Requisitos Funcionais
- A página de login apresenta, além do formulário, um bloco **“Novidades”** (ou título equivalente) listando itens curtos (título + descrição opcional).
- O bloco é **legível em mobile e desktop** (layout responsivo; não quebra o formulário).
- O conteúdo é **estático no código** (arquivo de dados versionado), sem migração de banco nesta entrega.
- Não exibe dados sensíveis, credenciais ou informações internas de infraestrutura.

## 3. Contratos e Interfaces
- **Entrada:** Lista tipada de itens (título, texto opcional, tipo opcional para selo visual, data opcional).
- **Saída:** HTML acessível (títulos hierárquicos, lista semântica ou artigos curtos).

## 4. NFRs
- **Performance:** Sem chamadas extras de rede só para o card; renderização no servidor junto à página.
- **Acessibilidade:** Região complementar identificável; contraste adequado com o tema dinâmico (cores de configuração).

## 5. Migração / Rollback
- Não há migração. Rollback: remover componente e import na página de login.

## 6. Abertos / Fora de Escopo
- CMS ou edição via UI; internacionalização; RSS.

## Checklist
- [x] Card visível na página de login com lista de novidades
- [x] Layout responsivo junto ao formulário
- [x] Fonte de dados versionada e fácil de atualizar
- [x] Sem dados sensíveis no texto
- [x] Compatível com tema de cores das configurações (variáveis CSS já aplicadas na página)
- [x] Critérios verificáveis manualmente
