# Spec: Compositor de Orçamento — Blocos Dinâmicos e Aninhamento Livre

**ID:** 20260226120000000
**Status:** Aguardando aprovação
**Data:** 2026-02-26
**Branch:** feature/16-budget-compositor

---

## 1. Contexto e Objetivo

O fluxo atual de edição de orçamentos usa uma hierarquia rígida de dois níveis (Local → Trecho). Essa estrutura não suporta orçamentos complexos onde o cliente precisa organizar o documento da forma que preferir — criando seções, subseções, agrupamentos arbitrários e inserindo diferentes tipos de conteúdo em qualquer ponto.

**Objetivo:** Substituir a aba "Ambientes" por um **Compositor** baseado em blocos tipados com aninhamento livre. O orçamento passa a ser uma árvore de blocos onde:

- **Sessões** são blocos-contêiner que podem conter outros blocos (inclusive sub-sessões)
- **Componentes** são blocos-folha que representam conteúdo (texto, local/ambiente, trecho, galeria de imagens, etc.)
- **Novos tipos de componente** são adicionados sem nenhuma migração de banco — basta registrar um novo `type` string e criar o componente React correspondente

**Inspiração:** Modelo de blocos do Notion — qualquer bloco pode ser contêiner de outros blocos; a estrutura do documento é definida pelo usuário, não pelo sistema.

---

## 2. Escopo

**Dentro desta spec:**
- Tabela `budget_block` com aninhamento recursivo via `parent_id`
- Catálogo inicial de tipos: `session`, `text`, `location`, `section`
- Campo `use_compositor: boolean` no `budget` para distinguir orçamentos novos dos existentes
- UI: aba "Compositor" com sidebar de árvore hierárquica + painel de conteúdo
- Numeração automática e hierárquica dos blocos-sessão (1 → 1.1 → 1.1.1…)
- `budget_item` adaptado para referenciar um `budget_block` de tipo `section`

**Fora desta spec:**
- Migração de orçamentos existentes (aba "Ambientes" permanece inalterada)
- Drag-and-drop para reordenar blocos
- Tipos futuros: `image_gallery`, `summary`, `checklist`, `cover`, `table` (adicionados em specs futuras sem migração de banco)
- Geração de PDF para orçamentos compositor (spec separada)

## 3. Modelo de Dados

### 3.1 Princípio central

Uma única tabela `budget_block` representa todos os nós da árvore do orçamento. O campo `type` (string livre) determina o componente React que renderiza o bloco. O campo `props` (objeto JSON) armazena os dados específicos de cada tipo. Adicionar um novo tipo de componente **não requer alteração de schema**.

### 3.2 Tabela `budget_block`

```sql
DEFINE TABLE budget_block SCHEMAFULL;
DEFINE FIELD budget_id    ON TABLE budget_block TYPE record<budget>;
DEFINE FIELD parent_id    ON TABLE budget_block TYPE option<record<budget_block>>;
-- null = bloco raiz (nível 1 na árvore)
DEFINE FIELD type         ON TABLE budget_block TYPE string;
-- Catálogo inicial: 'session' | 'text' | 'location' | 'section'
-- Extensível: qualquer string nova é um tipo válido
DEFINE FIELD label        ON TABLE budget_block TYPE string DEFAULT "";
-- Nome exibido no sidebar e no cabeçalho do painel
DEFINE FIELD order_index  ON TABLE budget_block TYPE int DEFAULT 0;
-- Posição entre os irmãos (filhos do mesmo parent_id)
DEFINE FIELD props        ON TABLE budget_block TYPE object DEFAULT {};
-- Dados específicos do tipo — ver seção 3.4
DEFINE FIELD created_at   ON TABLE budget_block TYPE datetime VALUE time::now();
DEFINE FIELD updated_at   ON TABLE budget_block TYPE datetime VALUE time::now() READONLY;
```

### 3.3 Campo novo na tabela `budget`

```sql
DEFINE FIELD use_compositor ON TABLE budget TYPE bool DEFAULT false;
```

Orçamentos novos (criados após esta feature): `use_compositor = true`.
Orçamentos existentes: mantêm `use_compositor = false`, aba "Ambientes" inalterada.

### 3.4 Adaptação de `budget_item`

```sql
DEFINE FIELD block_id ON TABLE budget_item TYPE option<record<budget_block>>;
-- Substitui section_id para orçamentos compositor
-- Aponta para um budget_block de tipo 'section'
```

`section_id` existente permanece para compatibilidade com orçamentos antigos.

### 3.5 Props por tipo (contrato de dados)

Cada tipo define o shape do campo `props`. O banco não valida — a validação é feita na Server Action com Zod.

| Tipo | Props |
|------|-------|
| `session` | `{ collapsed?: boolean }` |
| `text` | `{ content: string }` — HTML gerado pelo Tiptap |
| `location` | `{ description?: string }` — HTML do editor rico |
| `section` | `{ description?: string }` — HTML do editor rico |

> **Convenção para tipos futuros:** Cada novo tipo documenta seu shape de `props` em `.agent/pazini/09-compositor-block-types.md` antes de ser implementado.

### 3.6 Estrutura da árvore (exemplo)

```
budget (use_compositor = true)
│
├── budget_block { type:'session', label:'Área Produção', parent_id: null, order_index: 0 }
│   ├── budget_block { type:'location', label:'Galpão', parent_id: <sess1>, order_index: 0 }
│   │   └── budget_block { type:'section', label:'Linha A', parent_id: <loc1>, order_index: 0 }
│   │       └── budget_item { block_id: <sect1> } (produtos)
│   ├── budget_block { type:'text', label:'', parent_id: <sess1>, order_index: 1 }
│   │   props: { content: '<p>Observação...</p>' }
│   └── budget_block { type:'session', label:'Sub-área Norte', parent_id: <sess1>, order_index: 2 }
│       └── budget_block { type:'location', label:'Sala', parent_id: <subsess>, order_index: 0 }
│
└── budget_block { type:'session', label:'Área Administrativa', parent_id: null, order_index: 1 }
    └── budget_block { type:'location', label:'Recepção', parent_id: <sess2>, order_index: 0 }
```

### 3.7 Numeração hierárquica automática

A numeração é calculada no cliente percorrendo a árvore. Somente blocos do tipo `session` contribuem para a numeração; componentes folha herdam o número do ancestral `session` mais próximo.

```
Sessão raiz (order 0)             →  "1"
  Sub-sessão (order 0)            →  "1.1"
    Sub-sub-sessão (order 0)      →  "1.1.1"
  Sub-sessão (order 1)            →  "1.2"
Sessão raiz (order 1)             →  "2"
  Sub-sessão (order 0)            →  "2.1"
```

Blocos não-`session` dentro de uma sessão não geram novo nível numérico; são componentes daquele nó.

## 4. Server Actions (`budget-compositor-actions.ts`)

Todas as ações retornam `{ success: boolean, error?: string, data?: T }`.

### 4.1 Leitura

```ts
getCompositorTreeAction(budgetId: string)
// Retorna a árvore completa de budget_blocks + budget_items do orçamento
// Query recursiva ou múltiplas queries agrupadas no servidor
// Retorno: BudgetBlock[] (com children aninhados no cliente)
```

### 4.2 Blocos

```ts
addBlockAction(params: {
  budgetId: string
  parentId: string | null  // null = raiz
  type: string             // 'session' | 'text' | 'location' | 'section' | qualquer futuro
  label: string
  afterIndex?: number      // inserir após essa posição entre irmãos
})
// Cria bloco, calcula order_index, retorna { success, blockId }

updateBlockAction(blockId: string, patch: {
  label?: string
  props?: Record<string, unknown>
})
// Atualiza label ou props (merge parcial)

deleteBlockAction(blockId: string, budgetId: string)
// Remove o bloco e todos os descendentes (cascata manual)
// Remove também budget_items vinculados via block_id

moveBlockAction(blockId: string, newParentId: string | null, newIndex: number)
// Reposiciona bloco na árvore (reordenação futura)
```

### 4.3 Itens (adaptação)

```ts
addItemToBlockAction(blockId: string, budgetId: string, productId: string, quantity: number)
// Igual ao addItemAction atual, mas usa block_id em vez de section_id
// Só válido para blocos de tipo 'section'
```

### 4.4 Adaptação em `createBudgetAction`

```ts
createBudgetAction(title, code)
// → SET use_compositor = true  (orçamentos novos)
```

## 5. Tipos TypeScript

```ts
// budget-compositor-types.ts

export type BlockType = 'session' | 'text' | 'location' | 'section' | string
// string aberto para extensibilidade

export interface BudgetBlock {
  id: string
  budgetId: string
  parentId: string | null
  type: BlockType
  label: string
  orderIndex: number
  props: Record<string, unknown>
  createdAt: string
  // calculados no cliente:
  children: BudgetBlock[]
  number: string         // ex: "1.2.1" — calculado pela função buildTree()
  depth: number          // profundidade na árvore (0 = raiz)
}

export interface CompositorTree {
  blocks: BudgetBlock[]  // árvore aninhada
  items: Record<string, BudgetItem[]>  // blockId → items
}
```

### Função `buildTree(flatBlocks, flatItems)`

Converte a lista plana de `budget_block` em árvore aninhada, calculando `children`, `number` e `depth` de cada nó. Executada no cliente após o fetch. Sem lógica de numeração no banco.

## 6. Interface do Usuário

### 6.1 Detecção de modo no `BudgetWorkspace`

```
budget.use_compositor === true  → exibe aba "Compositor"
budget.use_compositor === false → exibe aba "Ambientes" (inalterada)
```

Dados e Preview permanecem iguais em ambos os modos.

### 6.2 Layout geral (aba "Compositor")

Mesma estrutura de duas colunas da aba "Ambientes":

```
┌──────────────────────────────────────────────────────────────┐
│ [Dados]  [Compositor]  [Preview]                             │
├───────────────────────┬──────────────────────────────────────┤
│ SIDEBAR (árvore)      │ PAINEL DE CONTEÚDO                   │
│                       │                                      │
│ ▼ 1 Área Produção     │  ← renderiza o componente do bloco  │
│   ▼ 1.1 Sub-norte     │    selecionado no sidebar            │
│       🏠 Galpão       │                                      │
│         ≡ Linha A     │                                      │
│       ¶  [texto]      │                                      │
│ ▼ 2 Área Admin        │                                      │
│   🏠 Recepção         │                                      │
│                       │                                      │
│ [+ Nova Sessão]       │                                      │
└───────────────────────┴──────────────────────────────────────┘
```

**Ícones no sidebar por tipo:**
- `session` → seta expand/collapse (►/▼) + número
- `location` → 🏠 (ou ícone `MapPin`)
- `section` → ≡ (ou ícone `Layers`)
- `text` → ¶ (ou ícone `FileText`)
- Tipos futuros → ícone registrado junto ao tipo

### 6.3 CompositorSidebar

**Responsabilidades:**
- Renderiza a árvore recursivamente (componente `BlockTreeNode`)
- Suporta aninhamento visual via indentação proporcional à profundidade
- `session` → título clicável para selecionar + botão expand/collapse
- Qualquer bloco → hover revela `[+ Adicionar]` (dropdown: "Sub-sessão", "Local", "Trecho", "Texto livre") e `[⋯]` (menu: renomear, excluir)
- Blocos não-`session` não têm botão `[+ Adicionar]` (não são contêineres)
- Botão `[+ Nova Sessão]` fixo no rodapé do sidebar (adiciona na raiz)

**Interação `[+ Adicionar]` (hover em qualquer bloco):**
```
┌──────────────────┐
│ Sub-sessão       │  → cria budget_block { type: 'session', parent: este bloco }
│ Local (ambiente) │  → cria budget_block { type: 'location', parent: este bloco }
│ Trecho           │  → cria budget_block { type: 'section', parent: este bloco }
│ Texto livre      │  → cria budget_block { type: 'text', parent: este bloco }
└──────────────────┘
```

### 6.4 CompositorContent (Painel de Conteúdo)

Funciona como roteador: recebe o bloco selecionado e renderiza o componente correto.

```ts
// Registro de componentes — extensível
const BLOCK_RENDERERS: Record<string, ComponentType<BlockRendererProps>> = {
  session:  SessionBlockRenderer,
  text:     TextBlockRenderer,
  location: LocationBlockRenderer,
  section:  SectionBlockRenderer,
  // novos tipos: importar e registrar aqui
}

// Fallback para tipos desconhecidos
const UnknownBlockRenderer = () => <p>Tipo "{type}" não suportado nesta versão.</p>
```

#### SessionBlockRenderer
- Label editável (inline)
- Lista dos filhos diretos como cards compactos com ícone + nome + número
- Botão `[+ Adicionar]` com dropdown completo

#### LocationBlockRenderer
- Label editável
- Editor rico de descrição (Tiptap, debounce 1.5s)
- Galeria de imagens (componente `BudgetImageGallery` existente)
- Lista de filhos diretos (normalmente `section`s)

#### SectionBlockRenderer
- Label editável
- Editor rico de descrição
- Galeria de imagens
- Lista de produtos (`ItemsList` existente, linkado via `block_id`)
- Botões: `[+ Adicionar Item]`, `[+ Adicionar Grupo]`

#### TextBlockRenderer
- Editor rico Tiptap full-width
- Salva via `updateBlockAction` com debounce 1.5s
- Sem label visível (conteúdo é o próprio texto)

### 6.5 Numeração no sidebar

Calculada pela função `buildTree()` — apenas blocos `session` incrementam o contador. Exibida antes do label:

```
1 Área Produção
  1.1 Sub-área Norte
      🏠 Galpão          ← sem número próprio, pertence a 1.1
        ≡ Linha A        ← sem número próprio, pertence a 1.1
  1.2 Sub-área Sul
2 Área Administrativa
```

### 6.6 Mobile

- Sidebar recolhido por padrão
- Dropdown no topo listando a árvore (indentada por nível)
- Painel de conteúdo ocupa 100% da largura

## 7. Catálogo de Tipos de Bloco (Extensão Futura)

Para adicionar um novo tipo de componente, o desenvolvedor:

1. Cria o React component `<NomeTipoBlockRenderer />` em `compositor/renderers/`
2. Registra no objeto `BLOCK_RENDERERS` em `compositor-content.tsx`
3. Adiciona a entrada no dropdown `[+ Adicionar]` do sidebar
4. Documenta o shape de `props` em `.agent/pazini/09-compositor-block-types.md`

**Não é necessária migração de banco.** A tabela `budget_block` aceita qualquer `type` string.

Tipos planejados para specs futuras:
| Tipo | Descrição |
|------|-----------|
| `image_gallery` | Galeria de imagens standalone sem produtos |
| `summary` | Resumo de totais calculados automaticamente |
| `checklist` | Lista de verificação customizável |
| `cover` | Capa ou divisória visual no PDF |
| `table` | Tabela de dados customizada |

- Nenhuma migração de dados necessária
