## 1. Contexto e Objetivo

Esta spec consolida o backlog de melhorias identificadas nas telas de Orçamentos, Grupos de Produtos e Editor de Imagem (Annotator). Os itens foram levantados em uso real do sistema e agrupados por domínio para facilitar a implementação incremental.

**Objetivo:** Cobrir correções de bug e novas funcionalidades que tornam o sistema utilizável para o fluxo comercial completo.

**Escopo desta entrega:**
- Dentro: 14 itens descritos abaixo, organizados em 6 grupos temáticos.
- Fora: redesign visual geral, integração com ERP, multi-tenant, exportação DOCX.

## 2. Grupo A — Correções e Melhorias nos Grupos de Produtos

### A1 — Bug: Exclusão de grupo não funciona

**Contexto:** O botão de excluir grupo na tela `/dashboard/products/groups` não realiza a exclusão. O erro pode estar na Server Action `deleteProductGroupAction` ou na confirmação via `AlertDialog`.

**Comportamento esperado:**
- Clicar em "Excluir" abre `AlertDialog` de confirmação.
- Ao confirmar, a Server Action executa com sucesso:
  - Remove `group_id` do array `group_ids` de todos os produtos vinculados.
  - Deleta a imagem do grupo via `deleteFile()` se existir.
  - Deleta o registro `product_group` do SurrealDB.
- Toast de sucesso é exibido e a listagem é atualizada.
- Caso o grupo possua produtos vinculados: exibir contagem e pedir confirmação explícita antes de desvincular.

**Critérios de aceite:**
- [x] Clicar em excluir abre AlertDialog com nome do grupo e contagem de produtos vinculados
- [x] Confirmar exclui o registro e exibe toast "Grupo excluído com sucesso"
- [x] Produtos anteriormente vinculados não referenciam mais o grupo excluído
- [x] Imagem do grupo é removida do disco
- [x] Cancelar não altera nada

### A2 — Editar quantidade ao adicionar produto a um grupo

**Contexto:** Ao adicionar um produto a um grupo no formulário de grupos, não é possível editar a quantidade depois de adicionado — a única forma é remover e adicionar novamente.

**Comportamento esperado:**
- Na lista de produtos dentro do formulário de grupo, cada item exibe um campo numérico de quantidade inline (input `type="number"`, min 1).
- Alterar o valor atualiza imediatamente o estado local sem necessidade de remover/adicionar.
- A quantidade é salva junto com a relação produto-grupo ao salvar o formulário.

**Critérios de aceite:**
- [x] Campo de quantidade editável inline na lista de produtos do grupo
- [x] Alteração da quantidade reflete no estado sem recarregar a lista
- [x] Quantidade persiste ao salvar o grupo

### A3 — Formato em lista expansível para grupos no orçamento

**Contexto:** Na tela de orçamento, grupos de produtos são exibidos como "caixas" grandes. O novo formato deve ser em lista (igual aos produtos simples), com expansão ao clicar para revelar os produtos internos.

**Comportamento esperado:**
- Grupos aparecem como uma linha de lista com ícone de grupo + nome + quantidade total + preço total.
- Clicar no grupo expande (accordion) para mostrar a lista de produtos internos, cada um com sua quantidade e preço.
- Recolher: clicar novamente no grupo fecha o accordion.
- O estado expandido/recolhido é local (não persiste no servidor).
- Ação de remover o grupo permanece disponível (ícone de lixeira na linha).

**Critérios de aceite:**
- [x] Grupo exibido como linha de lista (não como card/caixa)
- [x] Clique expande e mostra produtos internos com quantidade e preço
- [x] Segundo clique recolhe a lista
- [x] Layout idêntico ao padrão de produtos simples

## 3. Grupo B — Orçamento: Quantidades e Mão de Obra

### B1 — Editar quantidade de produto dentro do orçamento

**Contexto:** Após adicionar um produto a um local/trecho do orçamento, não é possível alterar a quantidade — é necessário remover e adicionar novamente.

**Comportamento esperado:**
- Na lista de itens do trecho/local, a quantidade de cada produto é exibida como campo numérico editável inline (input `type="number"`, min 1).
- Ao alterar o valor e confirmar (blur ou Enter), o sistema chama uma Server Action `updateBudgetItemQuantityAction(itemId, quantity)`.
- Toast discreto confirma a atualização.
- O total do trecho e do orçamento recalcula automaticamente.

**Contrato da Server Action:**
```typescript
updateBudgetItemQuantityAction(
  itemId: string,
  quantity: number
): Promise<{ success: boolean; error?: string }>
```

**Critérios de aceite:**
- [x] Campo de quantidade editável inline na lista de itens do trecho
- [x] Alterar quantidade e sair do campo (blur) dispara atualização no servidor
- [x] Totais do trecho, local e orçamento recalculam após atualização
- [x] Erro exibe toast de falha sem perder o valor anterior
- [x] Funciona para produtos simples e produtos dentro de grupos

---

### B2 — Valor de mão de obra unitária por item no orçamento

**Contexto:** O orçamento precisa suportar um campo de "mão de obra" (MO) por item/produto, somado ao valor do produto para calcular o total.

**Regra de negócio:**
- Cada item do trecho tem um campo `labor_cost` (valor unitário de mão de obra, padrão `0`).
- Total do item = `(product_price + labor_cost) × quantity`.
- A MO é opcional (pode ser zero) e configurável por item individualmente.
- Exibir coluna "MO (R$)" editável inline na tabela de itens do trecho.
- O total consolidado do trecho e do orçamento deve considerar a MO.

**Alteração de schema:**
```sql
DEFINE FIELD labor_cost ON TABLE budget_item TYPE option<float> DEFAULT 0;
```

**Contrato da Server Action:**
```typescript
updateBudgetItemLaborCostAction(
  itemId: string,
  laborCost: number
): Promise<{ success: boolean; error?: string }>
```

**Critérios de aceite:**
- [x] Campo "MO (R$)" somente-leitura na tabela de itens (copiado do produto)
- [x] Total do item = (preço + MO) × quantidade
- [x] Total do trecho e do orçamento incluem MO
- [x] MO padrão zero não altera comportamento atual quando não preenchida
- [x] Preço copiado do produto no momento da inclusão (orçamentos fechados imunes a mudanças de preço)
- [x] Novo campo `labor_cost` adicionado ao schema `budget_item`

## 4. Grupo C — Editor de Imagem: Ferramentas Novas

### C1 — Seta a partir da imagem de produto (Product Sticker Arrow)

**Contexto:** Quando uma imagem de produto (product sticker) é adicionada ao canvas do annotator, não é possível desenhar uma seta diretamente a partir dela para um ponto da imagem principal. O usuário precisa adicionar uma seta separada e ajustar manualmente.

**Comportamento esperado:**
- Ao selecionar um `product_sticker` no canvas, um handle de "arrastar seta" aparece (ex: pequeno ícone de seta na borda do sticker).
- Arrastar esse handle cria uma nova seta vinculada ao sticker: o ponto de origem da seta segue o sticker ao movê-lo.
- A seta pode ser arrastada para qualquer ponto da imagem.
- A seta é uma anotação normal do tipo `arrow`, mas com `linked_from_sticker_id` referenciando o sticker pai.

**Critérios de aceite:**
- [ ] Handle de "arrastar seta" visível ao selecionar um product sticker
- [ ] Arrastar handle cria seta com origem presa ao sticker
- [ ] Mover o sticker move a origem da seta junto
- [ ] Seta pode ser excluída independentemente do sticker
- [ ] Sticker deletado remove também a seta vinculada

---

### C2 — Ferramenta de linhas com múltiplos pontos de quebra (Polyline)

**Contexto:** Atualmente o annotator suporta apenas setas (dois pontos). Falta uma ferramenta de linha poligonal (polyline) para desenhar contornos e formas irregulares.

**Comportamento esperado:**
- Nova ferramenta "Linha" na toolbar (ícone de polilinha).
- Modo de uso:
  1. Clique no canvas define o ponto inicial.
  2. Cada clique subsequente adiciona um segmento (linha reta).
  3. Duplo-clique ou tecla `Esc` finaliza o desenho.
- Linhas sempre retas entre pontos (não mão-livre).
- Configurações ao finalizar (popover ou painel lateral):
  - Tipo de linha: sólida, tracejada, pontilhada.
  - Espessura: 1–10px.
  - Cor: paleta `ANNOTATION_COLORS`.
- A polyline é armazenada como `tool_type: 'polyline'` com `geometry.points: [{x,y}, ...]` (coordenadas relativas 0–1).

**Alteração de tipos:**
```typescript
export interface PolylineAnnotation extends BaseAnnotation {
  tool_type: 'polyline';
  points: Array<{ x: number; y: number }>; // mínimo 2 pontos
  lineStyle: 'solid' | 'dashed' | 'dotted';
  strokeWidth: number;
}
```

**Critérios de aceite:**
- [ ] Ferramenta "Polyline" presente na toolbar
- [ ] Cliques sucessivos adicionam segmentos retos
- [ ] Duplo-clique ou Esc finaliza o desenho
- [ ] Configuração de tipo de linha, espessura e cor
- [ ] Polyline salva e carrega corretamente (coordenadas relativas)
- [ ] Polyline selecionável, movível e deletável como outros elementos

### C3 — Aprimorar caixa de texto: redimensionamento livre

**Contexto:** A caixa de texto (`text` annotation) tem tamanho fixo (200px). Precisa ser redimensionável livremente pelo usuário via drag nos cantos/bordas.

**Comportamento esperado:**
- Ao selecionar uma anotação de texto, handles de redimensionamento aparecem nos 8 cantos/bordas (via Konva `Transformer`).
- Arrastar os handles altera `width` e `height` da anotação.
- O texto dentro da caixa faz wrap conforme a nova largura.
- O tamanho mínimo é 80×30px.
- As dimensões são salvas em coordenadas relativas (0–1) junto com a posição.

> **Nota:** Cor, contorno, borda e tamanho de fonte já foram implementados via `feature/text-annotation-style` (mergeado em 2026-02-25). Esta tarefa cobre apenas o redimensionamento livre.

**Critérios de aceite:**
- [x] Handles de redimensionamento visíveis ao selecionar texto
- [x] Arrastar handle altera largura e/ou altura da caixa
- [x] Texto faz wrap dentro da caixa redimensionada
- [x] Tamanho mínimo respeitado (80×30px)
- [x] Novo tamanho persiste ao salvar e reabrir

## 6. Grupo E — Orçamento: Numeração Hierárquica

### E1 — Numeração hierárquica de Locais e Trechos

**Contexto:** O orçamento é composto por áreas numeradas conforme o template comercial. A tela deve refletir essa numeração e obedecer à hierarquia do documento.

**Regra de negócio:**
- O orçamento tem um número de "seção raiz" (ex: `5`), configurado no cadastro do orçamento.
- Locais recebem numeração: `5.1`, `5.2`, `5.3`, …
- Trechos recebem numeração: `5.1.1`, `5.1.2`, `5.2.1`, …
- A numeração é auto-calculada pela posição na lista (não persistida separadamente).
- Exibida na UI ao lado do nome: `5.1 — Galpão Principal`.
- Exibida no PDF da mesma forma.

**Implementação:**
- A numeração é derivada em runtime (sem campo extra no DB) com base em `order_index` dos locais e trechos.
- O número raiz da seção é um campo `section_number` (inteiro, padrão 1) no registro `budget`.

**Alteração de schema:**
```sql
DEFINE FIELD section_number ON TABLE budget TYPE option<int> DEFAULT 1;
```

**Critérios de aceite:**
- [x] Campo `section_number` no cadastro/edição do orçamento
- [x] Locais exibem numeração `N.x` onde N = section_number
- [x] Trechos exibem numeração `N.x.y`
- [x] Numeração recalcula automaticamente ao reordenar locais/trechos
- [x] PDF reflete a mesma numeração
- [x] Numeração começa em 1 quando `section_number` não definido

## 7. Grupo F — Orçamento: Duplicação

### F1 — Duplicar local ou trecho

**Contexto:** Locais e trechos frequentemente se repetem em um orçamento. A duplicação evita retrabalho.

**Comportamento esperado:**
- Botão "Duplicar" (ícone `Copy`) disponível no menu de ações de cada local e trecho.
- **Duplicar trecho:** Cria uma cópia exata do trecho com todos os seus itens, na sequência seguinte do mesmo local. A numeração hierárquica é recalculada automaticamente.
- **Duplicar local:** Cria uma cópia exata do local com todos os seus trechos e itens. A numeração hierárquica é recalculada.
- Imagens e anotações **não** são duplicadas nesta versão (somente estrutura de itens).
- O nome da cópia recebe sufixo " (cópia)" para diferenciação.

**Contratos:**
```typescript
duplicateBudgetSectionAction(
  sectionId: string,
  budgetId: string
): Promise<{ success: boolean; error?: string }>

duplicateBudgetLocationAction(
  locationId: string,
  budgetId: string
): Promise<{ success: boolean; error?: string }>
```

**Critérios de aceite:**
- [x] Botão "Duplicar" no menu de ações do trecho
- [x] Botão "Duplicar" no menu de ações do local
- [x] Duplicar trecho cria cópia com todos os itens, na posição seguinte
- [x] Duplicar local cria cópia com todos os trechos e itens
- [x] Nome da cópia recebe sufixo " (cópia)"
- [x] Numeração hierárquica recalcula após duplicação
- [x] Imagens não são duplicadas (comportamento documentado)

## 8. Grupo G — Bug: Observações limpas ao expandir/retrair

### G1 — Observações de locais e trechos perdidas ao mudar layout

**Contexto:** Ao preencher o campo de observações de um local ou trecho e então expandir/retrair a tela (fullscreen ou painéis), o texto digitado é apagado e não há botão de salvar visível.

**Causa provável:** O componente de observações é desmontado/remontado ao alterar o layout, perdendo o estado local não salvo.

**Comportamento esperado:**
- O texto das observações **não** é perdido ao expandir/retrair.
- Um botão "Salvar observações" fica sempre visível enquanto houver alterações não salvas (dirty state).
- Alternativamente: auto-save com debounce de 1,5s após parar de digitar.
- O texto salvo persiste ao navegar entre locais/trechos e ao recarregar a página.

**Implementação recomendada:**
- Mover o estado das observações para fora do componente que é desmontado (lift state up ou usar `useRef` estável).
- Ou: salvar automaticamente no blur do campo com Server Action.

**Critérios de aceite:**
- [x] Texto de observações não é perdido ao expandir/retrair a tela
- [x] Botão "Salvar" visível quando há alteração não salva (ou auto-save)
- [x] Auto-save com debounce de 1,5s após parar de digitar (se escolhido)
- [x] Texto salvo persiste ao navegar entre locais/trechos
- [x] Texto salvo persiste após recarregar a página
