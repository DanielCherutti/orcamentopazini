# 20260131120000000 - Budget Workspace (Workspace de Orçamentos)

Esta especificação define o **Workspace Único de Orçamentos** do sistema Pazini, uma tela integrada onde se cria e edita propostas comerciais com locais, trechos (seções), itens, upload de imagens, anotações visuais e exportação para PDF/DOCX.

## 1. Contexto e Objetivo

### 1.1 Problema
O sistema precisa de uma interface **fluida e unificada** para criar orçamentos de adequação de segurança em engenharia mecânica, permitindo:
- Cadastro de dados da proposta
- Estruturação hierárquica (Locais > Trechos > Itens)
- Upload e anotação de fotos dos ambientes
- Vinculação visual de produtos às fotos (stickers/numeração)
- Exportação profissional em PDF/DOCX/Impressão

### 1.2 Objetivo
Criar uma **tela única e integrada** (`/budgets/new` e `/budgets/budget/[id]` usam a MESMA interface) onde:
- Dados do orçamento são editáveis no topo
- Locais, trechos e itens são criados inline sem modais complexos
- Fotos são uploadadas e anotadas diretamente em cada trecho
- Status (rascunho/enviado/aprovado/rejeitado) controla a visibilidade
- Exportação gera documento pixel-perfect baseado no template referência

### 1.3 Referências
- Template: `refs/pazini-v1/docs/proposta-comercial-base-de-exemplo.pdf`
- Specs anteriores: `20260129165500001-budget-structure.spec.md`, `20260129170500000-budget-annotations.spec.md`, `20260129171000000-budget-output.spec.md`

## 2. Arquitetura da Interface

### 2.1 Fluxo Unificado (New + Edit)

#### Criação (`/budgets/new`)
1. Usuário acessa `/budgets/new`
2. Sistema cria automaticamente um Budget em modo rascunho (`status='draft'`)
3. Sistema redireciona imediatamente para `/budgets/budget/[id]`
4. Usuário preenche os dados e estrutura o orçamento no Workspace (mesma interface usada em edição)

#### Edição (`/budgets/budget/[id]`)
1. Usuário acessa `/budgets/budget/[id]` (mesma interface de criação, mas com dados carregados)
   - O `[id]` na URL é apenas o UUID (ex: `26bbffae-0ea2-4c5e-942c-3d10bef98148`), sem o prefixo `budget:`
2. **Workspace Completo**:
   - Header fixo com dados do orçamento e ações principais
   - Conteúdo organizado em abas (Dados, Ambientes, Preview/Exportação)
3. Alterações são salvas ao clicar "Salvar" (auto-save é opcional e pode ser adicionado depois)

### 2.2 Navegação em Abas (Progressive Disclosure)

Para reduzir carga cognitiva e organizar responsabilidades do Workspace, a interface é dividida em **3 abas**:

1. **Aba Dados**
   - Dados principais do orçamento: Cliente, Número (read-only), Datas e Condições comerciais, Descrição inicial.

2. **Aba Ambientes**
   - Layout de duas colunas:
     - **Sidebar esquerda**: Índice de locais (ambientes) clicáveis; botão "Adicionar Local" no rodapé.
     - **Área direita**: Ao clicar em um local, exibe toda a configuração dele (trechos, itens, cenas/fotos).
   - Hierarquia: **Locais > Trechos > Itens**
   - Upload/edição de foto por Trecho e abertura do editor de anotação/composição.
   - **Responsivo**: Em mobile (<768px), sidebar vira Select/dropdown no topo; painel abaixo ocupa toda largura.

3. **Aba Preview/Exportação**
   - Preview do documento final (PDF)
   - Ações de exportação/download e impressão.

## 3. Modelo de Dados

### 3.1 Entidades Principais

#### `budget` (Orçamento)
```sql
-- SurrealDB Schema
DEFINE TABLE budget SCHEMAFULL;
DEFINE FIELD client_id ON budget TYPE record<client>;
DEFINE FIELD created_at ON budget TYPE datetime DEFAULT time::now();
DEFINE FIELD updated_at ON budget TYPE datetime DEFAULT time::now() VALUE time::now();
DEFINE FIELD status ON budget TYPE string DEFAULT 'draft' ASSERT $value IN ['draft', 'sent', 'approved', 'rejected'];
DEFINE FIELD code ON budget TYPE string; -- "Proposta Comercial - 00001"
DEFINE FIELD title ON budget TYPE string;
DEFINE FIELD description ON budget TYPE string; -- Rich Text Tiptap
DEFINE FIELD total_value ON budget TYPE number DEFAULT 0;
DEFINE FIELD code_sequence ON budget TYPE number;

-- Campos Comerciais (SDD-pdf-engine)
DEFINE FIELD payment_terms ON budget TYPE string; -- "30/60/90 dias"
DEFINE FIELD delivery_time ON budget TYPE string; -- "10 dias úteis"
DEFINE FIELD validity_days ON budget TYPE number DEFAULT 15;
DEFINE FIELD issue_date ON budget TYPE datetime DEFAULT time::now();
```

#### `budget_location` (Local/Ambiente)
```sql
DEFINE TABLE budget_location SCHEMAFULL;
DEFINE FIELD budget_id ON budget_location TYPE record<budget>;
DEFINE FIELD name ON budget_location TYPE string; -- "Galpão Principal"
DEFINE FIELD description ON budget_location TYPE string OPTIONAL; -- Rich Text
DEFINE FIELD order_index ON budget_location TYPE number DEFAULT 0;
```

#### `budget_section` (Trecho)
```sql
DEFINE TABLE budget_section SCHEMAFULL;
DEFINE FIELD location_id ON budget_section TYPE record<budget_location>;
DEFINE FIELD budget_id ON budget_section TYPE record<budget>; -- Desnormalizado para queries
DEFINE FIELD name ON budget_section TYPE string; -- "Linha de Montagem"
DEFINE FIELD description ON budget_section TYPE string OPTIONAL;
DEFINE FIELD order_index ON budget_section TYPE number DEFAULT 0;
```

#### `budget_item` (Item de Produto)
```sql
DEFINE TABLE budget_item SCHEMAFULL;
DEFINE FIELD section_id ON budget_item TYPE record<budget_section>;
DEFINE FIELD product_id ON budget_item TYPE record<product>;
DEFINE FIELD quantity ON budget_item TYPE number ASSERT $value >= 1;
DEFINE FIELD unit_price ON budget_item TYPE number; -- Snapshot do preço
DEFINE FIELD total ON budget_item TYPE number; -- quantity * unit_price
DEFINE FIELD notes ON budget_item TYPE string OPTIONAL;
```

#### `budget_image` (Imagem do Trecho)
```sql
DEFINE TABLE budget_image SCHEMAFULL;
DEFINE FIELD section_id ON budget_image TYPE record<budget_section>;
DEFINE FIELD url ON budget_image TYPE string; -- Base64 ou S3 URL (imagem original)
DEFINE FIELD composed_url ON budget_image TYPE string OPTIONAL; -- Imagem achatada com anotações
DEFINE FIELD width ON budget_image TYPE number;
DEFINE FIELD height ON budget_image TYPE number;
```

#### `image_annotation` (Anotação na Imagem)
```sql
DEFINE TABLE image_annotation SCHEMAFULL;
DEFINE FIELD image_id ON image_annotation TYPE record<budget_image>;
DEFINE FIELD tool_type ON image_annotation TYPE string ASSERT $value IN ['step_number', 'arrow', 'text', 'rect', 'product_sticker'];
DEFINE FIELD style ON image_annotation TYPE object; -- { color, strokeWidth, opacity, ... }
DEFINE FIELD geometry ON image_annotation TYPE object; -- { x, y, points, width, height } em % relativos
DEFINE FIELD content ON image_annotation TYPE string OPTIONAL; -- Texto ou número
DEFINE FIELD linked_item_id ON image_annotation TYPE record<budget_item> OPTIONAL; -- Vínculo ao item
```

### 3.2 Relacionamentos
- 1 Budget → N Locations
- 1 Location → N Sections
- 1 Section → N Items
- 1 Section → N Images (geralmente 1 imagem principal)
- 1 Image → N Annotations

## 4. Funcionalidades Detalhadas

### 4.1 Criação de Orçamento

**Fluxo:**
1. Usuário acessa `/budgets/new`
2. Sistema cria rascunho automaticamente e redireciona para `/budgets/[id]`
3. No Workspace, o usuário preenche/ajusta os dados (Cliente, Condições, Descrição) e estrutura Ambientes
4. A criação do rascunho é feita pela Server Action `createBudgetAction`:
   - Gera `code` sequencial via `getNextBudgetNumberAction()`
   - Cria registro com `status='draft'`
   - Retorna `id`
5. Redirect para `/budgets/budget/[id]` (feito automaticamente pelo sistema)

### 4.2 Gestão de Locais

**Adicionar Local:**
- Componente `<InlineLocationCreator budgetId={id} onSuccess={refresh} />`
- Input simples com nome
- Server Action `addLocationAction(budgetId, name)`
- Refresh da página (ou optimistic UI)

**Excluir Local:**
- Botão ação "Excluir Ambiente"
- Confirmação: "Tem certeza? Todos os trechos e itens serão removidos."
- Server Action `deleteLocationAction(locationId, budgetId)`
- Cascata: Remove Sections > Items > Images > Annotations

### 4.3 Gestão de Trechos

**Adicionar Trecho:**
- Componente `<InlineSectionCreator locationId={id} budgetId={id} onSuccess={refresh} />`
- Input simples com nome
- Server Action `addSectionAction(locationId, budgetId, name)`

**Excluir Trecho:**
- Botão "X" no card do trecho
- Confirmação
- Server Action `deleteSectionAction(sectionId, budgetId)`

### 4.4 Gestão de Itens

**Adicionar Item:**
- Componente `<InlineItemCreator sectionId={id} budgetId={id} onSuccess={refresh} />`
- Busca de produto via Combobox `<ProductSelector />`
- Input quantidade
- Ao adicionar:
  - Buscar preço atual do produto
  - Calcular `total = quantity * unit_price`
  - Salvar snapshot de preço (para não depender de mudanças futuras)
- Server Action `addItemAction(sectionId, productId, quantity, budgetId)`

**Remover Item:**
- Botão "X" inline
- Server Action `deleteItemAction(itemId, budgetId)`

### 4.5 Upload e Anotação de Imagens

**Componente Principal:**
```typescript
<BudgetPhotoAnnotatorDialog
  budgetId={string}
  sectionId={string}
  availableItems={BudgetItem[]}
  trigger={<Button>Adicionar Cena</Button>}
  onSaved={() => refresh()}
/>
```

**Fluxo de Anotação:**
1. Usuário clica "Adicionar Cena" ou "Editar Cena"
2. Modal fullscreen abre
3. Se não tem imagem: Upload de arquivo
4. Se tem imagem: Carrega `<AdvancedImageAnnotator />`
5. Ferramentas disponíveis:
   - **Step Number (Numeração):** Balões ①②③ para indicar pontos
   - **Arrow:** Setas direcionais
   - **Text:** Caixas de texto fixo
   - **Rect:** Retângulos de destaque
   - **Product Sticker:** Drag & drop de produtos da lateral
6. Ao salvar:
   - Gera imagem composta (canvas achatado) via `stage.toDataURL()`
   - Salva `url` (original) + `composed_url` (anotada)
   - Salva anotações como JSON no banco
   - Server Action `saveBudgetImageWithAnnotations(...)`

**Estética (Screenpresso-like):**
- Todos os elementos têm **borda branca** e **sombra** para alto contraste
- Cores vibrantes (Magenta, Cyan, Lime, Red Safety)
- Retorno vetorial (SVG/Canvas) para qualidade

### 4.6 Recálculo de Totais

**Regras:**
- Total Item = `quantity * unit_price`
- Total Trecho = Soma dos `item.total`
- Total Local = Soma dos `section.total`
- Total Orçamento = Soma dos `location.total`

**Implementação:**
- Cálculo em tempo real no backend (query)
- Campo `budget.total_value` atualizado via trigger ou query computada
- UI mostra total atualizado após cada operação

### 4.7 Status do Orçamento

**Estados:**
- `draft` (Rascunho): Editável, não enviado
- `sent` (Enviado): Proposta enviada ao cliente
- `approved` (Aprovado): Cliente aceitou
- `rejected` (Rejeitado): Cliente recusou

**Transições:**
- Draft → Sent: Ao clicar "Enviar Proposta"
- Sent → Approved/Rejected: Ação manual
- Qualquer estado pode voltar a Draft para edição (com auditoria)

## 5. Exportação de Documentos

### 5.1 Geração de PDF

**Engine:** `@react-pdf/renderer`

**Estrutura do Documento (conforme `SDD-pdf-engine.md`):**
1. **Capa:**
   - Logo Pazini
   - Título "PROPOSTA COMERCIAL"
   - Número da proposta
   - Cliente (Nome - Cidade - CNPJ)
   - Data emissão
2. **Apresentação:**
   - Texto institucional (vem de `company_settings`)
3. **Detalhamento (Loop):**
   - Para cada Local:
     - Título do Local
     - Para cada Trecho:
       - Título do Trecho
       - **Imagem Anotada (`composed_url`)**
       - Tabela de Itens (Produto, Qtd, Preço Unit, Total)
4. **Resumo de Investimento:**
   - Tabela de totais por local
   - **Total Geral** (destaque)
5. **Condições Comerciais:**
   - Pagamento, Prazo entrega, Validade
6. **Termos e Aceite:**
   - Texto jurídico
   - Espaços para assinatura

**Preview/Exportação (contratos de navegação):**
- Preview do PDF: rota `/budgets/budget/[id]/pdf` (abre em nova aba ou em aba interna de Preview/Exportação)
- Download/Impressão: via ações disponíveis na aba de Preview/Exportação

### 5.2 Geração de DOCX

**Engine:** `docx` library

**Limitação:** Layout simplificado (conteúdo estruturado, não pixel-perfect)

**Implementação:**
- Server Action `generateProposalDOCXAction(budgetId)`
- Estrutura similar ao PDF, mas com tabelas e imagens básicas

### 5.3 Impressão Direta

**Implementação:**
- Botão "Imprimir" abre PDF em nova aba
- `window.print()` no cliente
- Usa mesma engine de PDF

### 5.4 Anexos de Manuais Técnicos

**Feature:** Merge de PDFs
- Cada produto tem campo `technical_manual_url` (PDF)
- Ao gerar proposta com "Incluir Manuais" marcado:
  - Usar `pdf-lib` para concatenar PDFs
  - Resultado: Proposta + Manual Produto 1 + Manual Produto 2 + ...

## 7. Server Actions

### 7.1 Budget Management
- `createBudgetAction(client_id, title, ...data)` → `{ success, data: { id } }`
- `updateBudgetAction(id, updates)` → `{ success }`
- `getBudgetAction(id)` → `{ success, data: Budget }`
- `getBudgetFullTree(id)` → `{ success, data: BudgetTree }` (com hierarquia completa)
- `getNextBudgetNumberAction()` → `{ success, data: { formattedCode } }`
- `updateBudgetStatus(id, status)` → `{ success }`

### 7.2 Hierarchy Management
- `addLocationAction(budgetId, name)` → `{ success, data: { id } }`
- `deleteLocationAction(locationId, budgetId)` → `{ success }`
- `addSectionAction(locationId, budgetId, name)` → `{ success, data: { id } }`
- `deleteSectionAction(sectionId, budgetId)` → `{ success }`
- `addItemAction(sectionId, productId, quantity, budgetId)` → `{ success, data: { id } }`
- `updateItemQuantity(itemId, quantity, budgetId)` → `{ success }`
- `deleteItemAction(itemId, budgetId)` → `{ success }`

### 7.3 Image & Annotations
- `saveBudgetImageWithAnnotations(data)` → `{ success }`
  ```typescript
  data = {
    budgetId, sectionId, url, composedUrl, width, height,
    annotations: ImageAnnotation[]
  }
  ```

### 7.4 Export
- `generateProposalPDFAction(budgetId)` → Stream PDF
- `generateProposalDOCXAction(budgetId)` → Blob DOCX
