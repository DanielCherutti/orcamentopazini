# Remoção de usuário do portal

## 1. Contexto e Objetivo
- **Contexto:** Administradores cadastram usuários em **Configurações → Usuários**; hoje só é possível inativar ou reativar.
- **Objetivo:** Permitir **excluir definitivamente** um registro de `portal_user`, quando fizer sentido operacionalmente.
- **Escopo:** Apenas usuários do portal (`portal_user`). Fora: outros tipos de usuário ou tenants futuros.

## 2. Requisitos Funcionais
- Usuário autenticado pode solicitar a remoção de outro usuário do portal a partir do fluxo de gestão já existente.
- Antes de aplicar a remoção, o sistema exige **confirmação explícita** na interface (evitar clique acidental).
- Após remoção bem-sucedida, o registro deixa de existir no banco; a lista de usuários reflete a mudança.
- O sistema **não permite** remover o usuário cuja sessão está ativa (o próprio operador logado).
- O sistema **não permite** uma remoção que deixe **zero usuários** no portal.
- O sistema **não permite** uma remoção que deixe **nenhum usuário ativo** (mesma regra de negócio da inativação).

## 3. Contratos e Interfaces
- **UI/UX:** Na lista de usuários, ícone de exclusão por linha com confirmação em diálogo dedicado; mensagens de erro visíveis quando a ação for bloqueada ou falhar.
- **Server Action:** Entrada com identificador do usuário alvo validado; retorno de sucesso ou mensagem de erro genérica para o cliente (sem vazar detalhes internos).
- **Banco:** Exclusão do registro na tabela de usuários do portal. Sem migração de esquema.

## 4. Fluxos e Estados
- **Fluxo feliz:** Clicar no ícone de excluir na linha → confirmar no diálogo → registro excluído → lista atualiza (e o modal de gestão fecha se estiver aberto para aquele usuário).
- **Alternativos:** Erro de autorização, validação de negócio (própria conta, último usuário, último ativo), falha de persistência — mensagem clara e estado da UI preservado quando aplicável.

## 5. Dados
- Remoção física do documento `portal_user` alvo. E-mail único pode ser reutilizado em novo cadastro depois.

## 6. NFRs
- **Segurança:** Somente sessão válida; validação forte do identificador do registro.
- **UX:** Confirmação obrigatória para ação destrutiva.

## 7. Guardrails
- Reutilizar padrões de Server Actions e componentes de UI já usados na mesma tela.

## 8. Critérios de aceite
- Remover um usuário que não é o logado e que não viola as regras de “pelo menos um ativo” → sucesso.
- Tentar remover a própria conta → bloqueado com mensagem adequada.
- Tentar remover quando seria o último usuário ou o último ativo → bloqueado com mensagem alinhada à inativação.

## 9. Testes
- **Manual:** Cenários dos critérios de aceite na tela **Configurações → Usuários**.

## 10. Migração / Rollback
- Não há alteração de esquema. Rollback: restaurar backup do banco se necessário.

## 11. Abertos / Fora de Escopo
- Auditoria formal de quem removeu (log dedicado); soft-delete em vez de exclusão física.
