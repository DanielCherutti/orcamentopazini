# Spec: Aba Escopo + Bloco ESCOPO no Compositor

**ID:** 20260304120000000
**Status:** Implementado parcialmente
**Branch:** feature/19-budget-scope
**Prioridade:** Alta

---

## 1. Contexto e Motivação

O compositor de orçamentos gerencia blocos de documento (sessões, trechos, texto livre). Atualmente os locais — ambientes físicos do escopo de trabalho com suas seções, itens e fotos — não têm uma área dedicada no compositor.

O cliente precisa de dois espaços separados:

- **Orçamento**: o documento comercial montado livremente no compositor
- **Escopo**: o levantamento técnico por local (ambientes, trechos, produtos, fotos)

Um bloco especial `ESCOPO` inserido no compositor determina o ponto do documento onde o conteúdo do Escopo será expandido — tanto na visualização quanto no PDF final.

---

## 2. Layout Geral: 3 Abas

A tela de orçamento retorna ao modelo de 3 abas. Cada aba ocupa **100% da área disponível** abaixo do cabeçalho.

```
┌─────────────────────────────────────────────────────────────┐
│  HEADER  (título, status, ações: salvar / duplicar / status) │
├──────────────┬────────────────┬───────────────────────────────┤
│  Orçamento   │    Escopo      │          Impressão             │
└──────────────┴────────────────┴───────────────────────────────┘
│                    conteúdo da aba ativa (100% restante)      │
└───────────────────────────────────────────────────────────────┘
```

### 2.1 Aba Orçamento

Exatamente o `BudgetCompositor` atual, sem alterações de layout.
Adições: novo tipo de bloco `ESCOPO` (detalhado na seção 4).

### 2.2 Aba Escopo

Tela full-width, full-height, para gerenciar **locais** e todo o seu conteúdo.
Reutiliza a estrutura existente de `budget_location` / `budget_section` / `budget_item` (as mesmas tabelas do editor legado).

#### Estrutura visual

```
┌────────────────────┬──────────────────────────────────────────┐
│ PAINEL ESQUERDO    │ PAINEL DIREITO                           │
│ (sidebar ~280px)   │ (conteúdo do local/trecho selecionado)   │
│                    │                                          │
│ + Adicionar Local  │  [Local: Sala de Reunião]                │
│                    │  Descrição: ________________             │
│ ▼ Sala de Reunião  │                                          │
│   ├ Trecho 1       │  ▼ Trecho 1                              │
│   └ Trecho 2       │     Descrição ________                   │
│                    │     Itens: [...tabela de produtos...]     │
│ ▼ Recepção         │     Fotos: [...galeria...]               │
│   └ Trecho 1       │                                          │
└────────────────────┴──────────────────────────────────────────┘
```

#### Painel esquerdo (sidebar do Escopo)

- Lista hierárquica: Local → Trechos (indentado)
- Botão **"+ Adicionar Local"** no topo
- Cada local: botão inline `+` para adicionar trecho, ícone de lixeira
- Cada trecho: ícone de lixeira
- Clique em local ou trecho seleciona e abre no painel direito
- ~~Seleção persiste na URL via query param (`?local=<id>&trecho=<id>`)~~ → **Desvio implementado:** seleção mantida em estado local (`useState`) — URL param adiado por simplicidade

#### Painel direito (detalhe)

**Quando um Local está selecionado:**
- Campo de nome do local (inline editável)
- Editor de descrição rica (Tiptap, mesmo do compositor)
- Galeria de fotos do local com anotações (idêntico ao `LocationRenderer` do compositor)
- Lista dos trechos com um resumo (nome + contagem de itens)

**Quando um Trecho está selecionado:**
- Campo de nome do trecho (inline editável)
- Editor de descrição rica
- Tabela de produtos (idêntica ao `SectionRenderer` do compositor):
  - Colunas: produto, qtd, unidade, custo de mão de obra, preço unitário, total
  - Adicionar produto via picker
  - Adicionar grupo de produtos
  - Reordenar por drag-and-drop
- Galeria de fotos do trecho com anotações

**Quando nada está selecionado (estado inicial):**
- Mensagem central: "Selecione um local ou adicione um novo para começar"

### 2.3 Aba Impressão

Renderiza o PDF em modo preview diretamente na aba (iframe ou embed) sem abrir nova janela.
Botão "Baixar PDF" no canto superior direito da aba.

> Detalhe da engine de PDF fora do escopo desta spec — usa a rota existente de PDF.

## 3. Armazenamento de Dados do Escopo

### 3.1 Tabelas utilizadas (já existentes)

| Tabela | Papel |
|--------|-------|
| `budget_location` | Locais do escopo. Campos: `budget_id`, `name`, `description`, `order_index`, `created_at` |
| `budget_section` | Trechos de um local. Campos: `location_id`, `budget_id`, `name`, `description`, `order_index`, `created_at` |
| `budget_item` | Produtos de um trecho. Campos: `section_id`, `product_id`, `quantity`, `unit_price`, `labor_cost`, `total` |
| `budget_image` | Fotos de local ou trecho. Campos: `budget_id`, `location_id`, `section_id`, `url`, `composed_url` |
| `image_annotation` | Anotações de cada foto |

**Nenhuma migração de schema é necessária.** Os orçamentos no modo compositor passarão a usar estas tabelas para o Escopo. Os orçamentos legados (`use_compositor=false`) continuam funcionando com a mesma estrutura.

### 3.2 Coexistência compositor + escopo

Um budget `use_compositor=true` pode ter simultaneamente:

- `budget_block` records → estrutura do compositor (Aba Orçamento)
- `budget_location` + `budget_section` records → estrutura do escopo (Aba Escopo)

Ambas as estruturas são independentes no banco e coexistem sem conflito.

## 4. Bloco ESCOPO no Compositor

### 4.1 Definição

Novo tipo de bloco: `type: "scope"`.

Comportamento: ao ser inserido no compositor, **marca a posição** onde todo o conteúdo da Aba Escopo (locais → trechos → itens → fotos) será expandido durante a renderização do documento e do PDF.

### 4.2 Restrições

- **Somente um** bloco ESCOPO por orçamento. Tentar adicionar um segundo exibe toast: "Já existe um bloco Escopo neste orçamento."
- Não pode ter filhos (sem subsessões dentro do ESCOPO).
- Não pode ser renomeado (label fixo: "ESCOPO").
- Pode ser reposicionado (movido na sidebar como qualquer outro bloco).
- Pode ser deletado (o conteúdo do Escopo na aba Escopo permanece; apenas o marcador é removido).

### 4.3 Aparência na Sidebar do Compositor

```
├ 1. Introdução          [session]
├ 2. ESCOPO              [scope] ← ícone distinto (ex: Layers ou Map)
│   (não expansível — sem filhos)
└ 3. Condições Gerais    [session]
```

- Ícone: `<Map />` (Lucide), cor primária — ~~`<Layers />`~~ ajustado na implementação
- Label: "ESCOPO" em maiúsculas, sempre
- Sem botões de adicionar filho
- Badge indicando quantos locais existem no Escopo: ex. `(3 locais)`

### 4.4 Aparência no Conteúdo do Compositor

Quando o bloco ESCOPO está selecionado ou visível no painel de conteúdo, exibe um card informativo:

```
┌─────────────────────────────────────────────────────┐
│  🗂 ESCOPO                                           │
│                                                     │
│  Este bloco expande o conteúdo configurado na       │
│  aba Escopo: 3 locais, 7 trechos, 42 itens.         │
│                                                     │
│  [→ Ir para aba Escopo]                             │
└─────────────────────────────────────────────────────┘
```

- Não editável diretamente aqui
- Botão "Ir para aba Escopo" muda para a aba Escopo

### 4.5 Adição do Bloco ESCOPO

Na sidebar do compositor, o menu de adicionar bloco inclui a nova opção:

```
Adicionar bloco:
○ Sessão
○ Local
○ Trecho
○ Texto livre
● ESCOPO  ← novo
```

Se já existir um bloco ESCOPO: a opção aparece desabilitada com tooltip "Já existe um bloco Escopo".

## 5. Expansão do Escopo no Documento

### 5.1 Visualização no compositor (Aba Orçamento)

O bloco ESCOPO no painel de conteúdo exibe apenas o card informativo (seção 4.4). **Não** renderiza o escopo completo inline no compositor — seria muito pesado e confuso de editar.

### 5.2 PDF / Impressão

Na geração do PDF, o bloco ESCOPO é expandido com todo o conteúdo da Aba Escopo, na ordem:

```
[Bloco anterior no compositor]

LOCAL: Sala de Reunião
  Descrição...
  Fotos do local...

  TRECHO: Trecho 1
    Descrição...
    Tabela de itens...
    Fotos do trecho...

  TRECHO: Trecho 2
    ...

LOCAL: Recepção
  ...

[Bloco seguinte no compositor]
```

> A spec de PDF geração fica para spec dedicada. Esta spec foca em estrutura de dados e UI.

## 10. Reordenação por Drag-and-Drop (pendente)

### 10.1 Escopo da funcionalidade

Permitir ao usuário reordenar **locais** e **trechos** na sidebar do Escopo arrastando e soltando, da mesma forma que os itens de produto já são reordenados no `SectionRenderer` do compositor.

### 10.2 Comportamento esperado

- Cada linha de local na sidebar é arrastável (handle de grip à esquerda).
- Cada linha de trecho dentro de um local também é arrastável (somente dentro do mesmo local — trechos não migram entre locais via DnD).
- Ao soltar, a ordem é persistida no banco via action de reordenação.
- Atualização otimista: a sidebar reflete a nova ordem imediatamente, sem aguardar resposta do servidor.

### 10.3 Implementação técnica

**Biblioteca:** `@dnd-kit/core` + `@dnd-kit/sortable` (já instalada no projeto — usada em `compositor-content.tsx`).

**Padrão a seguir:** idêntico ao `SectionRenderer` em `compositor-content.tsx`:
```tsx
<DndContext sensors={sensors} onDragEnd={handleDragEnd}>
  <SortableContext items={ids} strategy={verticalListSortingStrategy}>
    {/* itens com useSortable */}
  </SortableContext>
</DndContext>
```

**Actions necessárias** (a criar em `budget-hierarchy-actions.ts`):

| Action | Assinatura | Descrição |
|--------|------------|-----------|
| `reorderLocationsAction` | `(budgetId, orderedIds: string[])` | Atualiza `order_index` de cada `budget_location` na ordem recebida |
| `reorderSectionsAction` | `(locationId, orderedIds: string[])` | Atualiza `order_index` de cada `budget_section` na ordem recebida |

Implementação de `order_index`: atribui `index * 1000` para cada posição, permitindo inserções futuras sem reescrever todos os registros.

### 10.4 Componentes a modificar

- `ScopeSidebar` em `budget-scope.tsx`: adicionar `DndContext` em volta da lista de locais e handle de grip em `LocationNode`.
- `LocationNode` em `budget-scope.tsx`: adicionar `DndContext` em volta da lista de trechos e handle de grip nas linhas de trecho.

## 11. SSE — Live Reload do Escopo (pendente)

### 11.1 Contexto

O compositor já possui live reload via SSE implementado em:

- **Rota SSE:** `GET /api/compositor/[budgetId]/live` — abre LIVE SELECT no SurrealDB para `budget_block` e `budget_item` via WebSocket dedicado; envia eventos `{ type: "block" | "item", action }` para o cliente.
- **Hook:** `useLiveCompositor(budgetId, onRefresh)` em `hooks/use-live-compositor.ts` — assina `EventSource`, chama `onRefresh()` a cada evento recebido; reconexão automática nativa do `EventSource`.
- **Uso:** `BudgetCompositor` chama o hook passando `loadData` como `onRefresh`.

### 11.2 Extensão necessária para o Escopo

A rota SSE atual **não monitora** `budget_location` nem `budget_section`. Para o Escopo receber atualizações em tempo real:

**Opção A — Estender a rota existente** (preferida — sem nova rota):

Em `/api/compositor/[budgetId]/live/route.ts`, adicionar dois LIVE SELECTs adicionais:

```ts
uuid3 = await db.live("budget_location", (_action, result) => {
  const rec = result as Record<string, unknown>;
  const bid = String(rec?.budget_id ?? "");
  if (!bid.includes(budgetId)) return;
  send(JSON.stringify({ type: "location", action: _action }));
});

uuid4 = await db.live("budget_section", (_action, result) => {
  send(JSON.stringify({ type: "section", action: _action }));
});
```

**No hook `useLiveCompositor`**, adicionar os novos tipos ao filtro:
```ts
if (["block", "item", "location", "section"].includes(payload.type)) {
  onRefresh();
}
```

**Opção B — Hook separado** `useLiveScope(budgetId, onRefresh)` que assina a mesma rota `/api/compositor/[budgetId]/live` mas só reage a eventos `location` e `section`. Mais isolado, mas duplica a conexão SSE.

> **Decisão:** implementar Opção A — uma conexão SSE por orçamento, todos os tipos de evento na mesma rota.

### 11.3 Componentes a modificar

- `front/src/app/api/compositor/[budgetId]/live/route.ts`: adicionar LIVE SELECTs para `budget_location` e `budget_section`; limpar (`.kill()`) os novos UUIDs no `cleanup`.
- `front/src/hooks/use-live-compositor.ts`: ampliar o filtro de tipos para incluir `"location"` e `"section"`.
- `BudgetScope` em `budget-scope.tsx`: chamar `useLiveCompositor(budgetId, loadLocations)` para recarregar a sidebar ao receber eventos do Escopo.
