# 20260129165500001 - Budget Structure (Orçamentos)

Esta especificação define a estrutura de dados e as operações fundamentais para o módulo de Orçamentos do sistema Pazini, cobrindo a hierarquia de locais, trechos e itens, além dos cálculos financeiros básicos.

## 1. Contexto e Objetivo
- **Contexto**: O sistema precisa gerar orçamentos para adequação de segurança em engenharia mecânica.
- **Objetivo**: Implementar o CRUD de orçamentos e sua estrutura hierárquica (Orçamento -> Local -> Trecho -> Item) com cálculos automáticos.
- **Referência**: `orcamentos.md` e `PLAN-budget-system.md`.

## 2. Estrutura de Dados (Data Model)
O modelo de dados deve ser implementado no SurrealDB.

### 2.1 Entidades Principais

#### `budget` (Orçamento)
Representa o documento raiz do orçamento/proposta.
- `id`: record
- `client_id`: record<client>
- `created_at`: datetime
- `updated_at`: datetime
- `status`: string ('draft', 'sent', 'approved', 'rejected')
- `code`: string (Código amigável, ex: ORC-2024-001)
- `title`: string
- `description`: string (Rich Text opcional)
- `total_value`: number (Calculado)
- `code_sequence`: number (Sequencial automático para geração do code)

> **Regra de Negócio (Auto-numeração)**:
> O campo `code` deve seguir o padrão "Proposta Comercial - {SEQ}", onde {SEQ} é um número sequencial formatado (ex: 00001). Ao criar, o sistema deve contar quantos orçamentos existem + 1. O campo `code` virá preenchido automaticamente no formulário de criação do orçamento.

#### `budget_location` (Local)
Representa uma grande área física (ex: "Galpão A", "Setor de Usinagem").
- `id`: record
- `budget_id`: record<budget>
- `name`: string
- `description`: string
- `order_index`: number (Para ordenação visual)

#### `budget_section` (Trecho)
Subdivisão de um local (ex: "Esteira 1", "Torno CNC 02").
- `id`: record
- `location_id`: record<budget_location>
- `budget_id`: record<budget> (Desnormalização para queries rápidas)
- `name`: string
- `order_index`: number

#### `budget_item` (Item de Orçamento)
Produto ou serviço aplicado em um trecho.
- `id`: record
- `section_id`: record<budget_section>
- `product_id`: record<product>
- `quantity`: number
- `unit_price`: number (Cópia do preço do produto no momento da adição - Snapshot)
- `total`: number (quantity * unit_price - Calculado)
- `notes`: string (Observações específicas deste item)

### 2.2 Relacionamentos
- 1 Orçamento tem N Locais.
- 1 Local tem N Trechos.
- 1 Trecho tem N Itens.

## 3. Server Actions & Business Logic
As operações devem ser atômicas e garantir a consistência dos valores totais.

### 3.1 Gestão de Orçamentos
- `createBudget(data)`: Cria rascunho.
- `updateBudgetStatus(id, status)`: Altera status.
- `getBudgetFullTree(id)`: Retorna o orçamento com toda a hierarquia aninhada (Locais > Trechos > Itens).
    - Deve calcular totais em tempo de execução ou usar campos computados.
- `getNextBudgetNumberAction()`: Retorna o próximo número sequencial disponível para o código do orçamento, garantindo que não haja duplicação de números.

### 3.2 Manipulação da Hierarquia
- `addLocation(budgetId, name)`
- `addSection(locationId, name)`
- `addItem(sectionId, productId, quantity)`
    - *Regra*: Ao adicionar item, buscar preço atual do produto e salvar em `unit_price`.
    - *Regra*: Recalcular total do orçamento (ou garantir que query de leitura faça isso).
- `addGroupToSection(sectionId, groupId, budgetId)`
    - *Regra*: Adiciona todos os produtos do grupo como itens (quantidade 1, preço atual). Ver `20260202120000000-product-groups.spec.md`.

- `updateItemQuantity(itemId, quantity)`
    - *Regra*: Atualizar `total` do item.

- `removeItem(itemId)`

### 3.3 Visualização (UI Pattern)
- Seguir padrão definido em `02-listing-ui-pattern.spec.md` para a listagem de orçamentos (`/budgets`).
- Tela de Detalhes/Edição (`/budgets/budget/[id]`):
    - **Header**: Info do Orçamento + Status + Valor Total.
    - **Sidebar/Navegação**: Índice de Locais à esquerda (clicáveis); ao selecionar, painel direito exibe trechos e itens.
    - **Main Content**:
        - Visualização em lista hierárquica (Accordion para Locais/Trechos).
        - Botões para "Adicionar Local", "Adicionar Trecho", "Adicionar Produto", "Adicionar Grupo" (ver spec product-groups).
        - Edição inline de quantidade.

## 4. UI Components

### 4.1 BudgetHierarchyTree
Componente recursivo ou iterativo para renderizar a estrutura:
- **LocalCard**: Título, Botão Add Trecho, Botão Remover, Lista de Trechos.
- **SectionCard**: Título, Botão Add Item, Lista de Itens.
- **ItemRow**: Nome Produto, Preço Unit, Input Qty, Subtotal, Botão Remover.

### 4.2 ProductSelector
Combobox/Modal para buscar produtos ao adicionar em um trecho.
- Deve mostrar estoque (se houver) e preço atual.

### 4.3 ClientSelector
- Deve permitir buscar clientes existentes com dados reais do banco.
- Ao selecionar um cliente, exibe os detalhes completos do cliente no formato: "Nome - Cidade - CNPJ" (ex: "Madeireira Ponta Grossa Ltda - Ponta Grossa - 84.169.331/0001-82").
- A numeração automática deve ser "Proposta Comercial - XXXXX" (ex: "Proposta Comercial - 00006").
- O campo de número da proposta deve ser read-only e preenchido automaticamente.

## 5. Casos de Uso (User Stories)

1. **Criar Orçamento**: Usuário cria novo orçamento para Cliente X.
2. **Estruturar Locais**: Usuário adiciona "Galpão Principal".
3. **Detalhamento**: Dentro de "Galpão Principal", adiciona trecho "Linha de Montagem".
4. **Inserção de Produtos**: Busca "Guarda Corpo" e adiciona 10 unidades na "Linha de Montagem".
5. **Revisão de Valores**: Usuário vê que o total do trecho e do orçamento subiu automaticamente.
